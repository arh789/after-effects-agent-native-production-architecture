# Project Lifecycle

## Stages

1. **Intake**: define audience, platform, format, duration, sources, and output.
2. **Editorial**: clean the transcript, map its logic, condense it, and approve
   slide-level claims.
3. **Provisional build**: create black-background slides at ten seconds each.
4. **Audio lock**: place the final edited narration and align slide markers.
5. **Timing review**: listen in AE and write corrections back to the timeline.
6. **Asset production**: brief, generate, select, and register backgrounds.
7. **Assembly**: import backgrounds, loops, watermark, and optional seam effects.
8. **Visual QA**: export reference frames, inspect, correct, and repeat.
9. **Finishing**: preserve intentional manual AE edits and render final outputs.
10. **Publishing**: create thumbnail, metadata, transcript, captions, and article
    handoff.
11. **Archive**: mark the project final and record reusable lessons.

## Approval Boundaries

The user remains authoritative for condensed wording, slide claims, final timing,
asset selection, visual taste, and publication. The agent can prepare, implement,
measure, and recommend, but must record provisional work as provisional.

## Status Rule

`PROJECT_STATUS.md` must identify the current stage, approved inputs, provisional
inputs, known problems, latest outputs, and one concrete next action.
